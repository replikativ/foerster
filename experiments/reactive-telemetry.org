#+TITLE: Reactive telemetry with resumable SCMC

* Purpose

This example updates an application-owned posterior when telemetry arrives,
rebuilds it after a historical correction, and runs a speculative update in
a fork without changing the parent. It uses a reviewed fixed-shape numeric
model. It does not claim automatic static admission of arbitrary simulators.
The paper and its frozen measurements are unchanged.

* Model and data

For each observation window i, with measured standardized load x_i:

  alpha ~ Normal(-2, 1.5)
  beta  ~ Normal(0, 1.5)
  failures_i ~ Binomial(requests_i, logistic(alpha + beta*x_i))

The simulator uses alpha=-2 and beta=2. There are 300 windows with eight
requests each, at 21 possible load values. The first 60 cover low loads,
the next 120 cover intermediate loads, and the final 120 cover high loads.
The posterior is nonconjugate. Its parameter correlation changes from about
+0.70 to -0.65 as the load coverage changes, while beta's posterior SD falls
by more than a factor of four. Predictions beyond early load coverage are
uncertain. These are conditional predictions, not causal effects of load.

An independent rectangular quadrature computes the reference posterior.
It aggregates binomial counts at each load, a sufficient statistic, while
the SCMC implementation scores individual windows. The grid covers
alpha in [-6,1] and beta in [-3,6]. Spacings 0.1 and 0.05 agree to within
0.005 posterior SDs in means and 0.5% in SDs; boundary mass is below 1e-7.
Binomial constants cancel only in the normalized reference calculation;
the SCMC likelihood includes them.

* Runtime path

The source signal contains a revision, base revision, scorer identity, and
an immutable vector of observations with unique IDs. A tracked Spin owns
one synchronous consumer; a Spindel runtime atom stores its inference state
inside the current world. Inference runs before resetting that atom, never
inside a retryable swap callback. The fixture awaits the reactive drain
before reading a published result and closes its contexts afterward.

The library now exposes scmc/start, scmc/append-batch and scmc/result.
The existing scmc/scmc entry point delegates to these operations. Numeric
movement and resampling still use the shared population engine. A global
step offset preserves the existing RNG keys when pausing and resuming.
Direct comparison with the pre-refactor SCMC implementation on the nonlinear
fixture produced identical particles, coreset, normalizer and move counts.
Snapshots contain persistent vectors and pure model functions; they are
in-memory values, not serialized model artifacts.

Append updates retain the population and coreset. A replacement replays
the corrected observation log from the last persistent snapshot before its
first changed window. The owner keeps the prior's state and the eight most
recent snapshots, taken every four batches (60 windows) at batch boundaries
of a replay from the prior. Randomness is keyed by global step, so the
snapshot replay is equal (=) to a replay of the whole corrected log from the
prior, with compression active and with low-ESS splits (a split retries
within its batch and never moves a snapshot boundary); its likelihood cost
is that of the replayed suffix. Appends that start inside a batch make the
state depend on the append history; no snapshot is taken from such a state,
and a later correction still replays from a snapshot on the grid. Replays
start from snapshots, never from the caller's options, and scmc/initial
reproduces a run's initial state with its recorded seed. A weighted
representative cannot generally be deleted as though it represented just
one original window. The application deliberately retains its audit log for replay;
only the inference state's memory is bounded by population and coreset.
The fixture's snapshot-prefix checks can scan the observation log; it makes
no end-to-end O(delta) runtime claim.

The fixture rejects stale revisions, conflicting duplicate revisions,
duplicate observation IDs, invalid observations, and scorer changes. It
accepts identical duplicate publications as no-ops. A fork receives a
separate speculative update; the parent's revision, particles and published
result remain unchanged.

* Weight health and recovery

The fixture tries batches of 15 windows. If a candidate update's pre-resample
ESS is below 10% of the population, it discards that candidate and retries
smaller batches from the persistent parent state. It publishes the minimum
accepted ESS fraction and the number of splits. This is adaptive scheduling,
not an unbiased-evidence or convergence guarantee.

Repairing undercounted failures in ten old windows (60-69) replays the 240
windows from the snapshot at window 60 and requires five splits in the
demonstration. An extreme single observation (10,000 requests with no
failures at high load) produces :needs-recovery with :reason :low-ess; it
does not commit a candidate revision. Tempered assimilation or a different
proposal is future recovery work. Refusal does not imply the posterior is
undefined.

Every accepted receipt explicitly reports posterior accuracy as
:not-assessed. ESS measures weight degeneracy, not posterior fit. Offline
validation adds separately computed reference errors. A nine-probe full-log
coreset audit reports centered log-likelihood error, removing irrelevant
additive constants. That audit requires retained data and is not a bounded
streaming diagnostic or a general convergence certificate.

* Accuracy and cost

SCMC compresses with GIGA and then refits GIGA's weights by nonnegative
least squares on the points it selected, as the reference implementation
does (=:refit :nnls=, the default; =:refit :none= reproduces the earlier
GIGA-only projection bit for bit). The sweep uses 800 particles, budgets 8,
32, 64, 128 and 300, and three inference seeds. Budget is the maximum
retained number of representatives and the GIGA iteration budget; fewer
distinct representatives may result. Each step evaluates every likelihood
once per particle state: the batch for the weights, the expanded coreset at
each move proposal. Values at the particles are cached in the state for the
next step's start states and for compression.

On the original stream, budget 128 gives final mean errors below 0.09
posterior SDs and SD errors below 3%. It retains 35-37 windows at the
final revision (at most 127 between steps; 142 with a batch) and uses
2.58-2.59 million likelihood evaluations, versus 5.28 million for the
uncompressed budget-300 runs. These counts include compression fitting
but exclude the independent audit and quadrature. They are not a
cross-system speed benchmark. Before the refit and the likelihood cache
the budget-128 runs used 3.93-3.96 million evaluations (errors below 0.11
SD) and the budget-300 runs 7.8 million.

Budget 8 still shows systematic bias after the load coverage changes:
0.39-0.75 posterior SDs of mean error (1.03-1.12 without the refit)
despite final ESS above 70% of population. Budget 32 is within 0.083 SD
(0.54-0.64 without the refit). This failure case is retained in the
validation; it should not be hidden by a favorable prediction metric or by
high ESS. The nine-probe audit's centered RMS error is 0.31-0.42 log units
at budget 8, versus 0.0003-0.008 at budget 128.

The selected budget also passes posterior checks on two independently
simulated streams. These checks establish behavior on this fixture, not
reliability for arbitrary nonlinear simulators or language-model factors.
The normalizer remains explicitly unverified, and compressed SCMC results
are labeled approximate populations.

In the reactive demonstration the appends cost 0.29, 1.11 and 1.18
million evaluations, the correction 3.45 million from the snapshot at
window 60 (3.74 million replaying all 300 windows from the prior), and the
speculative one-window append in a fork 0.06 million.

* Long streams (experiment E1)

The 300-window stream is only 2.3 times the budget, so total cost cannot
show that SCMC's per-update cost is bounded. A longer pilot in the review
found transient coreset-posterior bias of 1-2 posterior SDs at budgets
64-256 in the middle of a 3000-window continuous-load stream, without the
refit; the refit or a projection fitted on an inflated cloud reduced it.
=reactive-telemetry-long= runs that experiment: a continuous-load stream
(load uniform on [lo, lo+1), so no finite sufficient statistic over loads),
6000 windows with coverage low 20%, mid 40%, high 40% (optionally returning
to low), two data seeds, three inference seeds and 800 particles. Its arms
share the SCMC engine: full-history resample-move (IBIS), SCMC at budgets
32, 128 and 512, and a uniform reservoir of the same sizes. It records, per
update, likelihood evaluations by phase, wall time, retained factors and
pre-resample ESS, and at 20 checkpoints the error against a recentred
121x121 quadrature. Variants are arms such as =[:scmc 128 {:refit :none}]=
or =[:scmc 128 {:projection-inflation 3}]=.

=:projection-inflation k= is a research option and a deviation from the
UAI 2021 algorithm, off by default: GIGA is fitted at the particles spread
by k about their mean. It costs N times the expanded coreset size in
likelihood evaluations per compression.

The full configuration takes about 1.5 hours and has not been run here. A
smoke run (600 windows, 100 particles, one seed) finishes in 30 seconds:

#+begin_src sh
clojure -M:telemetry-long /tmp/telemetry-long.edn :windows 600 :particles 100 \
  :data-seeds '[7]' :seeds '[1]' :checkpoints 4 \
  :arms '[[:full] [:scmc 32] [:scmc 128] [:scmc 32 {:refit :none}] [:reservoir 32]]'
#+end_src

It writes the EDN result and a TSV summary (total and last-update
evaluations, largest retained set, worst and final error over checkpoints).

* Reproduction

No Raster, Python bridge, language model or GPU is needed by this example.

With src and experiments on the classpath:

#+begin_src clojure
(require '[org.replikativ.foerster.reactive-telemetry :as telemetry])

;; Append, correction replay, fork isolation and recovery refusal.
(telemetry/reactive-demo {:particles 800 :memory 128 :seed 31})

;; Full budget sweep, references and machine-readable receipts.
(telemetry/-main "/tmp/reactive-telemetry.edn")

;; Numerical and lifecycle validation, including independent streams,
;; snapshot replay and a smoke run of the long-stream experiment.
(require '[org.replikativ.foerster.reactive-telemetry-test]
         '[org.replikativ.foerster.reactive-telemetry-long-test])
(clojure.test/run-tests
 'org.replikativ.foerster.reactive-telemetry-test
 'org.replikativ.foerster.reactive-telemetry-long-test)
#+end_src

The portable library tests live in test/.../scmc_stream_test.cljc.
The longer numerical checks live beside the experiment and are run
explicitly. Receipts and validation logs are under
experiments/results/reactive-telemetry/.

The main entry point also writes .fits.tsv and .updates.tsv beside its EDN
output. A standalone figure can be regenerated using matplotlib:

#+begin_src sh
python3 experiments/plot_reactive_telemetry.py experiments/results/reactive-telemetry/results.edn
#+end_src

The saved figure shows predictive means, parameter mean errors against
quadrature, and inference likelihood-evaluation counts. It does not show
credible intervals or assert convergence from the plotted means alone.

Validation of the implementation (review branch, SCMC refit, likelihood
cache and snapshot replay): the experiment namespaces pass 9 tests / 144
assertions; the full JVM suite passes 417 tests / 4,880 assertions with a
3 GiB heap; the directly affected JVM namespaces (scmc, scmc-stream,
population-path) pass 24 tests / 183 assertions. Lint and formatting are
clean. The ClojureScript suite was not run (no node_modules in the
review worktree). The receipts under experiments/results/reactive-telemetry/
were regenerated with this code in a 2 GiB REPL.

Production follow-up remains the ObservationUpdatePlan compiler: retain
observation-value expressions and input/effect footprints, prove row-local
factorization and fixed latent support, and derive the factor evaluator.
This fixture does not substitute runtime checks for those missing proofs.
